# Precedent Spine Implementation Plan

> Amended 2026-11-07 against the product amendment spec. Supersedes the 2026-11-06 version.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The shared spine of the `precedent` package: point-in-time typed events from GDELT 2.0 and SEC 8-K filings, resolved prediction markets typed to the same event key, user-supplied prices and abnormal returns, a deterministic text typer with two optional model seams behind one protocol, and (research extra) a leak-tested Qlib ablation; then a schema-constrained language-model parser behind the same interfaces.

**Architecture:** An ICM workspace with one Python package, `precedent` (distribution `precedent-engine`). `precedent.spine` is deterministic code ported from the tested design listings, except three modules that may send text to a model. Every event source is rule-typed first (CAMEO codes, 8-K items), so the first milestones need no model. Free text (market questions, typed-in queries) goes through `spine/typers/`: rules by default, Anthropic or Ollama over `httpx` when the owner opts in. Qlib and LightGBM sit behind the `research` extra; the core install runs without them.

**Tech Stack:** Python >=3.11, uv 0.13.7 with `uv.lock`, hatchling, `src/` layout. Core: pandas 3.1, numpy 2.4, pydantic 2.14, pyarrow, httpx, `mcp>=2,<3`, Pillow. Extra `research`: pyqlib 0.9.7, lightgbm 4.7, scipy, pyyaml, networkx. Extra `dev`: pytest 9, pytest-cov, ruff. The parser track adds a local llama.cpp server.

**Spec:** `docs/superpowers/specs/2026-11-07-precedent-product-amendment.md` (the amendment) on top of `docs/superpowers/specs/2026-11-06-predate-design.md` (the design). Tested reference code: `docs/superpowers/specs/2026-11-06-predate-design-listings/`.

**Execution shape:** Tasks 1 to 4 run serially in one session; they define the interfaces every later task imports. Then these groups run in parallel subagents, each owning the files listed under File Structure: {5}, {6 then 7}, {8 after 6}, {9, 10}, {11, 12}, {13, 14, 15, 16}. Tasks 17 to 20 are owner-gated live runs and the parser track. Task 21 (independent verification) runs after Task 16 and before any track starts; it is numbered last only so that the cross-plan task numbers below stay fixed.

**Tracks that depend on this plan:** Precedent needs Tasks 1 to 8, 11 and 12 (its factors task also 13 to 15). Dream, Ripple and Mechanism cite tasks by the new numbers. Every track starts after the spine suite is green, Task 21 has passed, and the owner has merged.

**Old to new task numbers** (for the other plans): 1->1, 2->2, 3->3, 4->4, 5->9, 6->10, 7->11, 8->12, 9->13, 10->14, 11->15, 12->17, 13->18, 14->19, 15->20, 16->5 (GDELT events) and 16 (macro factors). Tasks 6, 7, 8 and 21 are new.

## Global Constraints

- Python `>=3.11`, uv with `uv.lock` committed, hatchling, `src/` layout. Distribution `precedent-engine`, import root `precedent`. Console scripts `precedent` -> `precedent.cli:main` and `precedent-mcp` -> `precedent.mcp_server:main`. Ruff line length 100, rules E, F, I, UP, B, SIM. No `addopts` in `pyproject.toml`. Tests run with `uv run pytest -q`.
- Core dependencies only in `[project.dependencies]`; `pyqlib`, `lightgbm`, `scipy`, `pyyaml` and `networkx` only in the `research` extra. A module that imports any of them is a research module: its test module starts with `pytest.importorskip("<that package>")`, so a core install with only the `dev` extra still passes. CI installs every extra.
- No provider SDKs. Only `spine/typers/anthropic_typer.py`, `spine/typers/ollama_typer.py` and `spine/openai_compat_extractor.py` send text to a model, over `httpx`; `spine/event_parser.py` calls an injected extractor. Everything else is deterministic. No model is called in tests or CI.
- `src/precedent/config.py` is the only module that names a model id, a base URL or a data-dir default (a test greps for it). Environment variables: `PRECEDENT_SEC_USER_AGENT`, `PRECEDENT_DATA_DIR` (default `~/.cache/precedent`), `PRECEDENT_TYPER` (default `rules`), `PRECEDENT_OLLAMA_BASE_URL`, `PRECEDENT_OLLAMA_MODEL`, `PRECEDENT_MODEL_BASE_URL` (llama.cpp parser runtime), `ANTHROPIC_API_KEY`. No contact detail or secret is written into the repository.
- `first_seen_utc` is required on every record. Naive timestamps are rejected. Time is tz-aware UTC internally. GDELT `SQLDATE` and EDGAR `filingDate` are never used for alignment.
- Every factor builder ships with a truncation-invariance test (design 4.5).
- `qlib.init` always passes `region="us"` and an SQLite experiment manager. In `NestedDataLoader` the price loader is first and `join="left"`. Label under convention C1: `Ref($open, -2)/Ref($open, -1) - 1`; `deal_price` is `open`; `label_horizon` is 2.
- No article text, price data, raw source files or model weights are committed. Git ignores `stages/*/output/`, `data/*` except `data/sample/`, `vendor/`, `.env`, `dist/`, `.venv/`, `__pycache__/`. Nothing in the repository displays or redistributes vendor prices.
- Unit tests never touch the network: every client takes an injected `Transport` and `Clock`. Test file basenames are unique across `tests/` (pytest's default import mode). Tests write only under `tmp_path`; CI checks `git status --porcelain` is empty afterwards.
- Zero spend. Nothing pushes, merges, downloads a model or dataset, calls a paid API or rents compute without the owner's yes; such steps are marked **owner gate** and name the source, size and cost first. The repository has no remote; the agent never pushes.
- Stage explicit files in every commit. Every result is recorded in `docs/STATUS.md` with one label: `SYNTHETIC`, `LIVE-DATA`, `LIVE-MODEL` or `NO LIVE RUN`. Every run-produced file under `docs/examples/` begins with `SYNTHETIC —`, `LIVE —` or `NO LIVE RUN —` (a test pins it).
- If Qlib, a data source or an API behaves differently from the spec, stop the task and report. Do not invent a substitute.
- The track ends with an independent verifier (Task 21), whose report is kept under `docs/verification/`; findings are fixed in `fix: independent-review findings` commits.

## Review Focus

1. A GDELT row whose `SQLDATE` is days before its `DATEADDED`: `first_seen_utc` and the session come from `DATEADDED`, and of two rows with the same key, actor country and session, the earlier `DATEADDED` wins. (Tests in Task 5.)
2. News after an early close (13:00 New York on 2024-11-29): the cutoff comes from the calendar, so the event rolls to the next session instead of landing on the half-day. (Test in Task 3.)
3. A model typer reply that is valid JSON but quotes an evidence span not in the text, carries an extra key, or ends in a refusal: `refused_invalid`, no key, never a guess; and `--dry-run` opens no socket. (Tests in Task 7.)
4. A resolved Polymarket market whose `outcomePrices` are not exactly 1 and 0: skipped and counted as `ambiguous`, never assigned a winner. (Test in Task 8.)
5. A factor row for an instrument with no price row on its session (halt, not yet listed): the left join drops it, and it is counted as `events_without_price_row` in the run manifest, never lost silently. (Test in Task 13.)

## Task Cycle

Every task uses the same five steps. The task lists only what is specific to it.

- **Step 1:** write the listed tests.
- **Step 2:** run them; they must fail for the stated reason (usually `ModuleNotFoundError` or `ImportError`).
- **Step 3:** implement the listed signatures.
- **Step 4:** run the task's tests, then the whole suite: `uv run pytest -q`, and `uv run ruff check .`. All green.
- **Step 5:** commit the listed files with the given message, and add a line to `docs/STATUS.md`.

A **Step 0** verifies recalled facts against the named source before any code; a mismatch stops the task. An **owner gate** step waits for the owner's yes in chat.
