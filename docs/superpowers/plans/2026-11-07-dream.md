**Goal:** Turn the event store and the link store into a living world state: a dated, append-only claim layer over them, a nightly batch that finds tensions between claims (and between text and price), detects silent shifts no single document states, lets stale claims expire, and writes a reviewable diff each morning. Nothing in the inputs is ever modified; the diff is a new vintage, and promotion of any resolution is a human act.

**Architecture:** A package `precedent.dream` on top of the spine, Precedent Task 2 (story clusters, `precedent.engine.story_clusters`) and Ripple Tasks 1 to 4 (link store, shocks). Dream is the content engine for the daily brief, not a standalone product (thesis section 3); its last task renders the brief. `Claim` records are bi-temporal (valid-from and valid-to in world time, recorded-at in pipeline time) and keyed to a source document and evidence span, following the pattern Graphiti/Zep use for edges but with no model in the loop. Detectors are deterministic functions over the claim, event, link and price stores as of a session's cutoff. The first milestone uses rule-built claims only, so it needs no language model; model-extracted claims and model-proposed resolutions are added last and are labelled hypotheses until a person promotes them.

**Tech Stack:** As the spine. Anything that imports Qlib or LightGBM (Task 7 only) needs the `research` extra (`uv sync --extra research`); the rest of the track runs on the core dependencies. Claims and tensions are JSON Lines like the other stores; DuckDB (already a transitive dependency of the data tooling, to be confirmed in Task 1 Step 0) is used read-only for the detector joins when the stores exceed memory, else pandas. No graph database server.

**Spec:** `docs/superpowers/specs/2026-11-06-predate-design.md`, sections 3.4, 4, 9.4 and 10.2. This plan is the spec for the Dream track.

**Depends on:** spine plan Tasks 1 to 4 and 9 to 15 (the old Tasks 1 to 11); Precedent Task 2 (`precedent.engine.story_clusters`); Ripple Tasks 1 to 4. Task 8 also needs spine Task 18 (the old Task 13). ## What the research check changed

Checked on 2026-11-07. Each item shapes a constraint or a test below.

- **Overnight consolidation is shipped, contradiction detection is not.** Anthropic's Dreams (Managed Agents preview) takes a memory store plus transcripts and writes a *new* store; the input is never modified and promotion is manual; it says stale or contradicted entries are replaced "with the latest value" but does not say how a contradiction is found, and documents no diff. OpenAI's ChatGPT dreaming describes background synthesis and no contradiction handling. The separate-output, manual-promotion design is adopted here as a constraint.
- **Graphiti/Zep** (Apache-2.0) invalidates an older edge when an LLM judges a new edge to contradict it, at ingest, and keeps history. Two reasons not to adopt it as the store: the spine forbids model calls outside parser modules, and Graphiti needs Neo4j, FalkorDB or Neptune (it lists Kuzu as deprecated). Its bi-temporal edge shape is adopted; its runtime is not.
- **KuzuDB is not a safe dependency.** The repository was archived and made read-only on 2025-10-10 and Apple agreed to acquire the company in February 2026. The attachment's suggestion of Kuzu is dropped. LadybugDB (MIT fork) and DuckPGQ exist but are unverified; the plan needs neither.
- **The closest open contradiction detector is CLAIRE/CLID** (Stanford, arXiv 2509.23233, code released): cross-document inconsistency detection reaching 75.1% AUROC with GPT-4o, on Wikipedia; editors found 64.7% more inconsistencies per hour with it. Its lesson for Task 3: candidate generation is cheap and structural (same subject, same attribute, overlapping validity), and the expensive judgement is applied only to candidates. The deterministic detectors here are the candidate generator; the model, when added, only judges candidates.
- **A 2023 workshop paper reports F1 89.6% for contradictions inside a single financial report** on proprietary data, with no code. No shipped product for overnight cross-source contradiction monitoring of company news was found. That absence is the gap this track fills; the search was limited, so it is recorded as unverified.
- **Letta's sleep-time compute** (arXiv 2504.13171) shows a second agent editing memory while idle at about 5x less test-time compute for equal accuracy, and names query predictability as the limit. Here the queries are predictable (the same detectors every night), which is the favourable case.

## Global Constraints

- Everything in the spine plan's Global Constraints applies. Only `parser_claims.py` and `parser_resolve.py` may call a language model.
- **Inputs are read-only.** The dream never writes to the event store, the link store or the price provider. It writes to `claims/`, `tensions/`, `shifts/` and `dreams/` under its own stage outputs, each append-only.
- **Bi-temporal claims.** Every `Claim` has `valid_from_utc` (acceptance time of its source document), `valid_to_utc` (expiry, or the time a later claim superseded it), and `recorded_utc` (when the pipeline wrote it). `claims_asof(cutoff_utc)` is the only read path and returns claims whose validity covers the cutoff and whose `recorded_utc` is at or before it. A backfilled dream for session `t` therefore sees exactly what a live dream on `t` would have seen.
- **Expiry is a write, not a delete.** "Pruned" means `valid_to_utc` was set by a dated rule or a dated superseding claim, with the reason recorded. Nothing is removed from any file.
- **Closed vocabularies.** `attribute` and `value` on a claim are enums from `references/dream/claim_vocabulary.json`. A model may not introduce an attribute.
- **Every claim and every tension names its evidence.** A claim has `source_doc_id` and, unless its `extractor_version` starts with `rules-`, a non-empty `evidence_span`. A tension names the two (or more) claim ids it is between.
- **Resolutions are hypotheses until promoted.** A `Resolution` has `status` in {`proposed`, `accepted`, `rejected`}; only `precedent dream promote` (Task 9) moves it from `proposed`, and only a person runs that.
- **The diff is the product.** Every nightly run writes `dream_<session>.md` and `dream_<session>.jsonl` with the same content. A run is idempotent: running the same session twice produces byte-identical output and appends nothing the second time.
- Every detector ships with a planted-case test (it must fire on a constructed tension or shift) and a quiet-case test (it must not fire on stationary synthetic data at more than its stated false-positive rate).
- Output always carries the line `Tensions and shifts are observations about documents and prices, not forecasts.`

## Review Focus

1. A claim from a filing accepted after the close: not visible to that session's dream. (Test in Task 1.)
2. A backfilled dream for session `t` run today must equal the dream that would have run on `t`: no claim recorded later than `t`'s cutoff may appear. (Test in Task 5.)
3. Two sources that disagree only because they describe different periods (Q1 guidance vs full-year guidance): not a tension; the attribute vocabulary carries the period. (Test in Task 3.)
4. A restated link or claim: it extends validity instead of creating a tension with itself. (Test in Task 1.)
5. A session with a feed outage: the dream says `no documents ingested for this session` and does not report a silent shift from the resulting zero. (Test in Task 4, using the spine's per-session coverage count.)

### Task 4: Silent-shift detectors

**Files:**
- Create: `src/precedent/dream/shifts.py`, Test: `tests/dream/test_shifts.py`

**Interfaces:**
- Produces: `event_rate_shift(events: pd.DataFrame, subject, session, sessions, window: int = 60, baseline: int = 250, threshold: float = 3.0) -> Shift | None`: Poisson rate test of the subject's event count over the last `window` sessions against the preceding `baseline` sessions; fires when the z-score exceeds `threshold`.
- Produces: `direction_drift(claims: pd.DataFrame, subject, session, sessions, k: float = 0.5, h: float = 4.0) -> Shift | None`: two-sided CUSUM on the sequence of `event_direction` values (+1, 0, -1) for the subject; fires when either cumulative sum exceeds `h`. CUSUM state is recomputed from the claims visible at the cutoff, never carried in memory, so a backfill and a live run agree.
- Produces: `link_churn(graph_now: pd.DataFrame, graph_then: pd.DataFrame, subject, session, threshold: float = 0.5) -> Shift | None`: Jaccard distance between the subject's link set now and `baseline` sessions ago; fires above `threshold`.
- Produces: `run_shift_detectors(stores, session, cutoffs, params) -> tuple[list[Shift], ShiftReport]`. Sessions flagged `feed_gap` in the coverage count are excluded from windows rather than counted as zero.
- Shift ids are stable the same way as tensions; a shift is reported on the session it first fires and again only if its statistic grows by more than 50% (proposed, in `detector_params.json`).
