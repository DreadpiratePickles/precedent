## 1. Purpose and scope

### 1.1 What you asked for

- A pipeline where a FinGPT-style model reads news and emits structured, point-in-time event data, and Microsoft Qlib does the modelling and backtesting. The language model never predicts prices as text.
- Coverage of five areas: architecture and event schema, look-ahead control, parser fine-tuning and inference, Qlib integration, and validation and backtesting.
- Then, with no fixed goal: something fascinating and useful that plays to the strengths of both. You chose two directions to build in parallel, **Precedent** and **Ripple**, each with its own implementation plan.

### 1.2 The one rule

The language model never forecasts. It reads, and emits structure: what kind of event this is, who is involved, what it is linked to, what it resembles. Qlib owns time and numbers, and price history decides what that structure is worth.

### 1.3 Assumptions (mine; correct any that are wrong)

### 1.4 Non-goals

- Live or paper trading, broker integration, order routing.
- Intraday bars.
- Real futures backtesting (margin, rolls, contract multipliers).
- A user interface beyond a command line and generated reports.
- The Flywheel and Rhyme directions. They stay as later options.

### 1.5 Success criteria (all thresholds proposed)

| ID | Criterion |
|---|---|
| S1 | The leakage test suite passes: truncation invariance, cutoff audit, and a deliberate one-session lead that the suite must detect (section 4.5). |
| S2 | A run manifest (input hashes, parser version, code commit) regenerates the factor panel byte for byte. |
| S3 | The ablation ladder (price only, then news, then Precedent, then Ripple) is produced under identical folds and costs, with results split at the base model's training cutoff. |

| R2 | Ripple factors add rank IC over both a return-correlation graph and a degree-preserving shuffled graph, in the post-cutoff window. If they do not, the report says so. |

## 3. Architecture (the spine)

### 3.1 Flow

```text
 SOURCES                01 INGEST              02 TRIAGE             03 PARSE
 SEC EDGAR filings ─┐   raw article store      dedupe, entity        language model +
 GDELT events/GKG  ─┼─► append-only,       ─►  pre-match, daily  ─►  JSON grammar ->
 other news         ─┘   content-hashed         cap (code only)       NewsEvent, validated

 04 ALIGN               05 FACTORS             06 DATASET            07 TRAIN
 available_utc,         direct news factors    Qlib handler:         LightGBM first,
 effective_session, ─►  Precedent factors  ─►  price features    ─►  then ensemble
 name -> instrument     Ripple factors         joined to news,
 (code only)            (code only)            label after cutoff

 08 EVALUATE                       09 BACKTEST
 purged walk-forward, rank IC, ─►  costed long-only simulation in Qlib,
 ablation ladder, leak tests       long-short accounting outside it
```

Only stage 03 calls a language model. Every other stage is deterministic code (rulebook principle 6). Each stage is one ICM stage with its own contract; the stage contracts are written in the spine plan, not here.

### 3.3 Event schema: what the model may emit

One article produces one JSON object. The model fills in meaning; it never fills in time or instrument identity.

| Field | Type | Notes |
|---|---|---|
| `schema_version` | `"1.0"` | |
| `event_type` | enum, 21 values | earnings, guidance, mna, capital_return, management_change, product, legal_regulatory, labor, supply_disruption, cyber_incident, credit_rating, macro_data_release, central_bank, fiscal_policy, trade_or_sanctions, armed_conflict, election_or_political, natural_disaster, commodity_supply, other, no_market_event |
| `actor` | object | `name`, `kind` (company, government, central_bank, regulator, international_org, person, other), `country_iso3` or null |
| `action` | string, up to 120 chars | Short verb phrase. |
| `impacted` | list, up to 8 | Each: `name`, `kind` (company, sector, commodity, country, index, currency), `ticker_hint` or null, `direction_step` in {-2, -1, 0, 1, 2} |
| `severity` | enum 1..10 | Anchored scale in the prompt (section 5.4). |
| `macro_direction_step` | enum {-2, -1, 0, 1, 2} | Risk-off to risk-on. Code maps it to [-1, +1] by dividing by 2. |
| `confidence` | enum low, medium, high | Code maps to 0.3, 0.6, 0.9. |
| `horizon` | enum | intraday, days, weeks, months, structural |
| `novelty` | enum | new, update, recap, opinion. Recaps and opinion are the commonest source of stale signal. |
| `is_scheduled` | boolean | Earnings dates and data releases are known in advance; surprises are not. |
| `evidence_span` | string, up to 200 chars | Copied word for word from the article. Code rejects the event if the span is not found in the text. |

This covers every field the brief listed (actor, action, impacted sectors and tickers, severity 1-10, macro direction -1 to +1, confidence, horizon) and adds event type, novelty, the scheduled flag and the evidence span.

Three design choices matter here:

1. **Every scored field is a closed enum.** Decoders disagree on numeric bounds (section 2), but all of them enforce enums. Model-emitted decimals are also poorly calibrated; five steps is as much resolution as the signal has.
2. **`ticker_hint` is a hint.** Models invent and misremember tickers, and tickers change over time. Code resolves `name` and the hint against a point-in-time security master; an unresolved name is recorded as unresolved, never guessed.
3. **`direction_step` describes the text, not the future.** It records whether the event as described is favourable or unfavourable for the entity. Whether that predicts returns is Qlib's question.

### 3.4 Event record: what code adds

The stored record wraps the model's object in a deterministic envelope.

| Field | Written by | Meaning |
|---|---|---|
| `article_id`, `body_sha256` | ingest | Identity and content hash of the exact text parsed. |
| `source` | ingest | Which feed. |
| `published_utc` | ingest | The publisher's own claim. May be missing, wrong, or revised. |
| `first_seen_utc` | ingest | Earliest moment we could have had the item (section 4.1). |
| `ingested_utc` | ingest | When our pipeline stored it. Audit only. |
| `available_utc` | align | `max(published_utc, first_seen_utc) + latency`. |
| `effective_session` | align | First session whose decision cutoff is at or after `available_utc`. |
| `parser_version` | parse | Base model id, adapter hash, prompt hash, schema version, runtime version. |
| `event` | parse | The validated model object from 3.3. |
| `resolved_impacts` | align | Instrument ids matched from `impacted`, with the match method. |

Records are append-only and keyed by (`article_id`, `parser_version`). Re-parsing with a new model or prompt writes a new vintage beside the old one. A backtest pins one parser version.

## 4. Look-ahead bias and temporal leakage

There are two different leaks. The first is in the plumbing: a row sees data that did not exist yet. The second is inside the language model: it was trained on text written after the events it is parsing. The first is solvable with code. The second can only be bounded.

### 4.1 Four clocks

| Clock | Example | Used for alignment? |
|---|---|---|
| Event time | The day the earthquake happened (GDELT `Day`) | No. |
| `published_utc` | The byline timestamp | Only as a lower bound. |
| `first_seen_utc` | GDELT `DATEADDED`, EDGAR `acceptanceDateTime`, or our own fetch time when running live | Yes. |
| `ingested_utc` | When our database row was written | Only when the pipeline was truly running live at that moment. |

The brief frames alignment as `published_utc` against `ingested_utc` plus a latency buffer. That is right for a live system, and wrong for a backfill: an article from 2019 ingested today has an `ingested_utc` in 2026. So the rule is:

```text
first_seen_utc = source availability stamp        (backfill)
               = our fetch time                   (live)
available_utc  = max(published_utc, first_seen_utc) + latency
```

`latency` covers fetch, parse and decision time. Proposed starting values: 30 minutes for GDELT-sourced items, 5 minutes for EDGAR. Once the pipeline runs live, set it to the 99th percentile of the measured `ingested_utc - first_seen_utc` and re-run.

A publisher clock is never trusted alone. A missing `first_seen_utc` is an error, not a default.

### 4.2 From timestamps to daily bars

Each session has one decision cutoff. An event belongs to the first session whose cutoff is at or after its `available_utc`. Weekend and holiday news rolls to the next session.

| Convention | Row for session t holds events available by | Trade at | Label | Purpose |
|---|---|---|---|---|
| C1 (default) | Close of t, 16:00 New York | Open of t+1 | `Ref($open, -2)/Ref($open, -1) - 1` | Standard. Price features at t are also known at the close. |
| C2 (lagged) | Close of t-1 | Open of t+1 | Same | Robustness. Real diffusion survives a day's delay; timestamp leakage does not. |
| C3 (pre-open) | 09:00 New York on t+1 | Open of t+1 | Same | Freshness experiment for overnight news. Only meaningful with trustworthy intraday timestamps. |

The label starts strictly after the cutoff in every convention. Qlib's own default label, `Ref($close, -2)/Ref($close, -1) - 1`, assumes entry at the close of t+1; we use opens so that the label matches `deal_price: open` in the backtest. That the daily strategy acts on the previous session's signal is `RECALLED` and gets its own test in the spine plan.

Under C1, news that arrives after the close is traded at the open two sessions later. That delay is deliberate for the first version; C3 measures what it costs.

### 4.3 Things that get revised

| Item | How it changes after the fact | Rule |
|---|---|---|
| Articles | Edited or corrected after publication | Keep the first version by content hash. A later version is a new record with its own `first_seen_utc`. |
| Parser output | A better prompt or adapter re-reads old articles | New vintage under a new `parser_version`. Never overwrite. |
| Macro data | GDP, payrolls and CPI are revised for months | Use ALFRED's first release (`output_type=4`) and vintages. |
| Filings | `filingDate` hides after-hours acceptance | Use `acceptanceDateTime`. |
| Adjusted prices | Every split or dividend restates the whole history | Fine for returns. Never use an adjusted price level as a feature, and record the provider build date. |
| Index membership | Today's S&P 500 list is not 2015's | Use dated membership. |
| Delisted names | Yahoo keeps only current listings | Free-data results are labelled exploratory until a delisting-inclusive source is bought. Survivorship flatters long-only results most. |
| Economic links (Ripple) | A supplier relationship ends or begins | Every link carries the acceptance time of the document it came from, and an expiry (section 9). |
| Precedent outcomes | An analog's 20-session response is unknown for 20 sessions | An analog is usable only after its response window has closed (section 8). |

### 4.4 The leak inside the language model

A model trained on text through year Y has read what happened after every event before Y. Asked to score the severity of a 2008 headline, it is not reading; it is remembering.

What the literature found (`SRC`, arXiv ids in the appendix):

- Lopez-Lira, Tang and Zhu: models recall exact pre-cutoff economic and financial values. Instructions to respect the date, and masking of entities and dates, do not stop it. There is no recall after the cutoff.
- Sarkar and Vafa: direct tests find look-ahead in pre-cutoff tasks. Censoring identifiers "is not always a valid strategy". They recommend models pretrained only on text from before the test period.
- Glasserman and Lin: with company names anonymized, in-sample results improved, because names also distract the model. Out of sample they found no look-ahead concern.
- He, Lv, Manela and Wu: models trained only on text available at each date (ChronoBERT, ChronoGPT) perform comparably on a news-return test, so they judge the bias "modest" there.

The rules that follow:

| # | Rule |
|---|---|
| L1 | The only clean out-of-sample window starts after the base model's training cutoff. Every headline claim comes from that window. Pre-cutoff results are reported separately and labelled contaminated. |
| L2 | Choose the base model by its cutoff date as well as its quality. An older base buys a longer clean window. Llama-3-8B's cutoff is March 2023 (`RECALLED`; confirm on the model card), which would leave about three and a half years of clean history today. |
| L3 | Run a vintage control. Re-parse a sample of pre-cutoff articles with a chronologically consistent model (`manelalab/chrono-gpt-instruct-v1-*`, about 1.55B parameters) and compare factor IC. A large pre-cutoff gap that disappears post-cutoff points to leakage. The small model is also a weaker reader, so this is suggestive, not proof. |
| L4 | Entity masking is an ablation to report, not a fix to rely on. |
| L5 | The schema has no price, return or outcome field, and the prompt forbids outside knowledge. This reduces the surface; per the findings above it does not close it. `severity` is the most exposed field. |
| L6 | Fine-tuning labels come from text only. The adapter never sees a return. |

### 4.5 Leak tests that run as code

| Test | What it does | What it proves |
|---|---|---|
| Truncation invariance | Build factors from all events and from only the events at or before t; rows up to t must be identical. | No factor depends on later events. Implemented for the news panel (listing A.4, `RAN`). |
| Cutoff audit | For every event, assert cutoff(effective session) >= `available_utc` and the previous cutoff < `available_utc`. | Alignment is exact. Implemented as a property test (listing A.3, `RAN`). |
| Positive control | Shift features one session earlier on purpose. Rank IC must jump. | The suite can detect a leak. A suite that cannot see a planted leak proves nothing. |
| Lag curve | Shift features 1, 2 and 5 sessions later. Rank IC should fade smoothly. | A cliff at lag 1 suggests the signal lived in timestamp error. |
| Cutoff split | Report every metric before and after the base model's cutoff. | Bounds the model-memory leak (L1). |

## 5. The parser: FinGPT, fine-tuning and inference

### 5.1 What we take from FinGPT

| FinGPT asset | Decision | Reason |
|---|---|---|
| FinGPT-Forecaster adapters | Not used | Free-text price predictions (section 2). |
| Multi-task adapters (sentiment, relation extraction, headline, entities) | Reference only | Outputs are labels and prose, not JSON. Base models are gated on Hugging Face. |
| Instruction datasets (`FinGPT/fingpt-finred-re`, `fingpt-ner`, headline, sentiment) | Optional auxiliary training data | Convertible to our schema's sub-tasks. |
| The recipe: LoRA (r=8) on an open 7-8B base | Adopted | Cheap to train, runs on one machine. FinGPT's own adapters use r=8, alpha=16 on all seven projection modules. |

The repository is MIT-licensed and still merges fixes (last push 2026-10-25) but has published no model since October 2024.

### 5.2 Prompt first, adapter second

A fine-tuned adapter is earned, not assumed (rulebook principle 1).

1. **Zero-shot baseline.** Base model plus grammar-constrained decoding plus the prompt in 5.4. No training.
2. **Gold set.** 300 articles (proposed): 150 filing excerpts and 150 news items, labelled by you with a stronger model as second annotator, disagreements resolved by hand. Split 200 for development and 100 held out. The held-out 100 are never used to tune a prompt or an adapter.
3. **Measure the baseline** on the development split (metrics in 5.5).
4. **Train an adapter only if the baseline misses its thresholds.** Training data: 3,000 to 5,000 articles labelled by the stronger model against the same schema from text alone, plus the gold development split.
5. **Accept the adapter only if it beats the baseline on the held-out 100.**

Prompt and adapter iteration is a ratchet loop under rulebook principle 17: the oracle is the metric script on the development split, the held-back check is the 100 held-out articles, and the runner counts iterations. Its `## Loop` contract is written in the spine plan.

LoRA settings to start from (`SRC` for the API, values proposed): PEFT `LoraConfig(r=16, lora_alpha=32, lora_dropout=0.05, target_modules=[q_proj, k_proj, v_proj, o_proj], task_type=CAUSAL_LM)`, TRL `SFTTrainer` with prompt-completion pairs so loss is on the JSON only, learning rate 1e-4, 2 to 3 epochs. On the Mac, `mlx_lm.lora` trains the same shape of adapter. A rented GPU is a spend that needs your yes.

### 5.3 Runtime and constrained decoding

| Runtime | Where | Schema-constrained call | Numeric bounds | Notes | Label |
|---|---|---|---|---|---|
| llama.cpp server | Mac (Metal) | `response_format` of type `json_schema`, or the `json_schema` body field | Integers only. "Unsupported features are skipped silently." | LoRA via `--lora`; a PEFT adapter converts with `convert_lora_to_gguf.py`. Patterns must start with `^` and end with `$`. | `SRC` |
| vLLM | NVIDIA GPU | Same `response_format`; offline `StructuredOutputsParams(json=...)` | Not rejected | `--enable-lora --lora-modules name=path`. The old `guided_json` fields are removed. Rejects `pattern` combined with length bounds. | `SRC` |
| xgrammar | Library | `compile_json_schema` plus a logits processor | Enforced | Docs advise describing the structure in the prompt as well. | `SRC` |
| Outlines 1.3.3 | Library | `model(prompt, JsonSchema(schema), max_new_tokens=...)` | Raises `UnsupportedNumericBound` | Default `max_new_tokens` is 20, which truncates. | `SRC` |
| MLX-LM | Mac | None built in | n/a | Schema decoding only through Outlines. | `SRC` |

Choice: llama.cpp on the Mac now, vLLM if a GPU is ever rented. Both accept the same OpenAI-style `response_format`, so one adapter serves both (spine plan Task 13; not yet written). Whether a LoRA adapter and grammar decoding work together is undocumented for both runtimes and is the first thing the parser track tests.

A grammar guarantees that the output parses. It does not guarantee that it is true. Every object is still validated by code: schema check, evidence-span check, entity resolution.

### 5.4 Making the model a parser, not a chatbot

- **One job, stated once.** The prompt asks for one JSON object and nothing else (full text in listing A.2).
- **No outside knowledge.** "Use only what the article states." This reduces the surface; it does not close the memory leak (section 4.4).
- **No forecasts.** The prompt says so, and the schema has nowhere to put one.
- **Anchored scales.** Severity: 1-2 routine or expected; 3-4 notable for one company; 5-6 material for one company or notable for a sector; 7-8 material for a sector or a national economy; 9-10 systemic or global.
- **Evidence or nothing.** The span must be found in the text, or the event is rejected.
- **An explicit way out.** `no_market_event` is a valid answer. Without it the model invents events to fill the schema.
- **Greedy decoding.** Temperature 0, fixed seed, one call per article, no retry with different sampling.
- **Outputs are the record.** Identical outputs across hardware and runtime versions are not guaranteed, so results are cached by (`body_sha256`, `parser_version`) and the cache is what backtests read.

### 5.5 Parser metrics (thresholds proposed)

| Metric | Threshold |
|---|---|
| Output parses and validates | 100% (by construction; anything less is a runtime bug) |
| Evidence span found in text | at least 95% |
| `event_type` agreement with gold | at least 80% |
| Impacted-entity F1 against gold | at least 0.75 |
| `severity` within 1 step of gold | at least 80% |
| Direction sign agreement | at least 85% |
| Same output on a second run | 100% on the same machine and runtime |

## 6. Qlib integration and factor engineering

### 6.1 How news enters Qlib

| Route | How | Verdict | Label |
|---|---|---|---|
| Static loader joined to price features | News panel as a DataFrame indexed (datetime, instrument); `NestedDataLoader([price_loader, news_loader], join="left")` | **Chosen.** Simple, and re-parsing needs no re-dump. | `RAN` |
| Custom binary fields | Dump `$news_signed` and friends with `dump_bin`, then use Qlib expressions such as `Mean($news_signed, 5)` | Later, if expression mining is wanted. Needs dense series and a re-dump per parser vintage. | `NOT RUN` |
| Qlib's point-in-time store | `P()` operator over `_q` and `_a` fields | Rejected. Built for periodic statements. | `SRC` |

Facts the handler depends on (`RAN` unless marked):

- Index levels must be `(datetime, instrument)`, in that order, with those names.
- With `join="left"`, the **first** loader's index wins. Price goes first; putting the sparse news loader first silently drops every row without news (6,000 rows became 1,468 in the probe).
- `LGBModel.fit` needs `qlib.init()` because it logs metrics. With mlflow 3.18 the default file store fails; point the experiment manager at SQLite.
- `qlib.init()` defaults to region `cn`: lot size 100 and a 9.5% price limit (`SRC`). Always pass `region="us"`.
- `DropnaLabel` is only allowed among the learn processors.

### 6.2 Direct news factors

Per event: `signed = direction * severity/10 * confidence_weight` and `attention = severity/10 * confidence_weight`. Age is counted in sessions since the effective session.

| Factor | Definition |
|---|---|
| `news_cnt_1d` | Events effective on t |
| `news_sev_max_1d` | Largest severity on t |
| `news_signed_1d` | Sum of `signed` on t |
| `news_novel_share_1d` | Share of events on t with novelty `new` |
| `news_signed_decay` | Sum of `signed * 0.5 ** (age / half_life_sessions)` over events up to 20 sessions old; half-life 3 sessions (proposed) |
| `news_attention_decay` | The same for `attention` |

A missing row means no news, so news columns are filled with 0. Price-feature gaps are left as NaN for the model to handle; a blanket fill would turn missing prices into zeros (listing A.5).

Planned in the spine plan, not in the listings: market-wide factors from macro events (`macro_direction_decay`), and their interaction with each stock's rolling beta. A value that is the same for every stock on a date cannot change a cross-sectional ranking by itself; the interaction can.

### 6.3 What Qlib is told about time

The label expression and the backtest's `deal_price` must agree with the alignment convention in 4.2. Under C1: label `Ref($open, -2)/Ref($open, -1) - 1`, `deal_price: open`, label horizon 2 sessions for purging.

### 6.4 Model choice

| Model | Verdict | Reason | Label |
|---|---|---|---|
| `LGBModel` (LightGBM) | **First** | Handles sparse, mixed-scale and missing features; fast enough for many purged folds and ablations; importances give a sanity check. | `RAN` (synthetic) |
| `DEnsembleModel` (DoubleEnsemble) | Second | Sample reweighting and feature selection suit a few noisy news factors among 158 price factors. Needs train and valid segments. | `SRC` |
| `GATs` | Not for Ripple | No explicit graph input. Needs PyTorch. | `SRC` |
| `HIST` | Later candidate for Ripple | Takes a stock-to-concept matrix. Details in section 9. | `SRC` |
| Transformer, Localformer, TRA (time-series variants) | Challenger only | Want dense sequences; news is sparse. Worth trying once LightGBM shows incremental IC. | `SRC` |
| PatchTST | Not planned | Not in Qlib. Could be wrapped through `GeneralPTNN`, which supports only MSE loss, and that path is unverified. Its channel-independent design suits long single-series history, not a sparse cross-sectional event panel. | `SRC` |

The principle: graph and text enter as features before they enter as architecture. If LightGBM cannot find signal in a propagated-shock feature, a graph network will not rescue it; it will only make the failure harder to see.

## 7. Training, validation and backtesting

### 7.1 Purged walk-forward

A row's label looks `label_horizon` sessions ahead (2 under C1). The last rows of a training window therefore have labels that reach into the next window. Purging removes them.

```text
gap = label_horizon + embargo
|---- train ----| gap |-- valid --| gap |-- test --|
                                         then step forward and repeat
```

- Purging applies between train and valid and between valid and test. Qlib's own `RollingGen(trunc_days=...)` only opens the gap before the test segment (`RAN`), so the folds come from our own function (listing A.6, `RAN`).
- `embargo` adds sessions beyond the label horizon. In pure walk-forward, training never follows testing, so it matters mainly for combinatorial splits.
- Combinatorial purged cross-validation (`skfolio.model_selection.CombinatorialPurgedCV`, BSD-3, `SRC`) is used once, on the final few candidates, to estimate the probability of backtest overfitting. The canonical reference is Lopez de Prado, *Advances in Financial Machine Learning* (2018), chapters 7 and 12.
- Every configuration ever scored on validation is logged in a results table. The count of trials is an input to any claim about the best one.
- The final test period is touched once.

### 7.2 Objective

| Option | Verdict | Reason |
|---|---|---|
| MSE on raw returns | No | Dominated by a few volatile names and days. |
| Cross-entropy on up or down | No | Discards magnitude and the cross-section. |
| MSE on a cross-sectionally rank-normalized label (`CSRankNorm`) | **First** | Close to optimizing rank agreement, and it is what `LGBModel` supports. |
| LambdaRank with per-date groups | Optional later | Needs a small custom model class, since `LGBModel` passes no group. |
| Negative Pearson IC per daily batch (listing A.7) | For neural challengers | Directly optimizes the reported metric. One trading day per batch. |
| Differentiable Sharpe | No | Couples the model to a portfolio rule and overfits a few hundred daily observations. |

The alpha model and portfolio construction stay separate. The model is selected on mean rank IC and ICIR across validation folds; information ratio after costs is reported from the backtest, not optimized.

### 7.3 Backtest assumptions

| Setting | Value | Basis |
|---|---|---|
| `region` | `us` | Lot size 1, no price limit (`SRC`). |
| `deal_price` | `open` | Matches the label (4.2). |
| Strategy | `TopkDropoutStrategy(topk=50, n_drop=5)`, long-only | Qlib cannot short (`SRC`). |
| `benchmark` | SPY | Must exist in the provider data. |
| `open_cost`, `close_cost` | 0.0005 each (5 bps per side), proposed | Covers commission and half-spread for liquid large caps. No primary figure for the half-spread was confirmed this session. Anchor for institutional size: Frazzini, Israel and Moskowitz report mean implementation shortfall of 13 bps on live trades (`SRC`). |
| Cost stress | Re-run at 10 and 20 bps per side | A result that dies at double the cost is not a result. |
| `min_cost` | 1.0 | Per-order minimum of a retail broker's fixed plan (from a search snippet, unverified). |
| `impact_cost` | 0.1, proposed | Qlib's rule: extra fee ratio = `impact_cost * (trade value / day's traded value) ** 2` (`SRC`, not executed). At 10% of the day's volume this adds 10 bps; at 1%, 0.1 bps. |
| Capacity | Report cost against the square-root law from the trade log | Qlib's impact is quadratic in participation and leaves the fill price unchanged. The empirical law is `impact = Y * daily_vol * sqrt(Q / V)` with Y of order one (Tóth et al., 2011, `SRC`). |
| Borrow | Outside Qlib | Long-short returns are computed from predictions and returns by our own accounting, charging a borrow fee on the short leg. Anchors: general collateral averaged 17 bps a year and specials 4.3% in D'Avolio (2002), a dated sample (`SRC`). Stress at 1% and 5%. |

Not modelled anywhere in this design: opening-auction slippage beyond the flat cost, taxes, and financing of leverage.

### 7.4 What gets reported

The ablation ladder, under identical folds and costs:

| Rung | Features |
|---|---|
| M0 | Alpha158 price features only |
| M1 | M0 plus direct news factors |
| M2 | M1 plus Precedent factors |
| M3 | M1 plus Ripple factors |

For each rung: mean rank IC, ICIR, gross top-minus-bottom spread, long-only excess return over SPY net of costs, turnover, maximum drawdown, and all of these split at the base model's cutoff. A rung that does not improve on the one below it in the post-cutoff window is reported as not helping.

## 8. Precedent: an analog engine and what-if simulator

### 8.1 What it does

For a real event, or a hypothetical one you type in, Precedent finds the most similar events from strictly earlier dates and reports what assets actually did afterwards, as a distribution with the precedents listed. It is an automated, conditional event study. The language model supplies event type and similarity. It never supplies the response.

### 8.2 Components

| # | Component | Job | Model call |
|---|---|---|---|
| P1 | Event key | A typed key built by code from the event record: `event_type`, actor kind, impacted kinds, country group, severity band (1-3, 4-6, 7-10), scheduled flag, direction sign. | None |
| P2 | Event text | One canonical line built by code from the tuple, with names replaced by role tokens, for example `[CENTRAL_BANK] of [COUNTRY]: raises policy rate; unscheduled`. Embedded by a local embedding model. | Embedding only |
| P3 | Response library | For every stored event and every asset in a fixed panel: abnormal return over 1, 5 and 20 sessions, measured from the first tradable open after the effective session. Each row records the session on which its window closed. | None |
| P4 | Retrieval | Apply the time guard, filter by type, rank by similarity, keep the top K (K = 30, proposed). | None |
| P5 | Aggregation | Similarity-weighted quantiles (10, 25, 50, 75, 90), hit rate, effective sample size, placebo comparison, shrinkage. | None |
| P6 | Outputs | The `predate whatif` command, Precedent factors for Qlib, and a calibration report. | Parser, for typed-in text only |

### 8.3 Rules specific to Precedent

| Rule | Statement |
|---|---|
| Time guard | An analog may serve a query only if its response window closed at or before the query's `available_utc`. This is checked per window: a 1-session response becomes usable long before the 20-session one. |
| Abnormal return | Market model: `AR = r - (alpha + beta * r_market)`, with alpha and beta estimated on sessions -250 to -21 before the event. The event window starts after the decision cutoff. Reference: MacKinlay (1997), Journal of Economic Literature 35(1) (citation `SRC`; the definitions are the standard ones and were not checked against the paper's text). Events that cluster in time overstate significance (Kolari and Pynnönen, 2010). |
| Stories, not articles | The same story is reported many times. Events are grouped into story clusters (same key and primary actor within 3 sessions, proposed). The first report is the event; later ones are updates. Without this, one story supplies thirty of its own precedents. |
| Effective sample size | Analogs whose windows overlap in calendar time are not independent. Sample size counts distinct, non-overlapping windows, and bands widen to match. |
| Placebo | Each response is compared with the same asset's abnormal return over the same window on random non-event dates. A median inside the placebo's middle 80% is reported as indistinguishable from an ordinary week. |
| Shrinkage | Reported centre = median * n_eff / (n_eff + 10) (proposed). |
| Refusal | With fewer than 8 usable precedents (proposed) the tool says so and lists the nearest ones without a band. |
| Embedding hindsight | An embedding model released after an event can encode what that event came to mean. Role tokens remove names, the embedding model's release date is recorded in `precedent_version`, and the key-only rung (no embedding) is the control. |

### 8.4 Baseline ladder

The language model has to earn its place against rules that cost nothing.

| Rung | Event typing | Similarity | Needs a model |
|---|---|---|---|
| B0 | None | Unconditional placebo distribution | No |
| B1 | Rules: 8-K item numbers for company events, GDELT CAMEO root code and actor class for world events, release name for macro data | Exact type match | No |
| B2 | Model-typed `NewsEvent` | Typed key match | Parser |
| B3 | Same as B2 | Key match plus embedding similarity | Parser and embedding |

Scoring is in time order: each held-out event's band is built only from earlier events. Metrics are pinball loss per quantile and band coverage. B1 is built first. It needs no language model, proves the response library and the time guard, and sets the bar.

8-K items expected to matter (`RECALLED`; the plan's first task checks them against the SEC form): 1.01 material agreement, 1.03 bankruptcy, 1.05 cybersecurity incident, 2.02 results of operations, 2.05 exit or disposal costs, 2.06 material impairment, 4.02 non-reliance on prior financial statements, 5.02 officer departure or appointment.

### 8.5 Outputs

**The what-if command.** Typed text goes through the parser to an event tuple, then through the same retrieval as a real event, as of now.

```text
$ predate whatif "<event described in plain words>"

parsed as      <event_type> / <actor kind> / severity band <b> / unscheduled
precedents     <n> found, <n_eff> independent, earliest <date>, latest <date>
asset   window   p10    median   p90    hit rate   vs ordinary week
<etf>   5        ...    ...      ...    ...        outside / inside
...
nearest precedents
<date>  <one-line description>  similarity <s>  <source document id>
...
These are past outcomes of similar events, not a forecast.
```

**Precedent factors**, per session and instrument, for events active on that session: `prec_car5_med`, `prec_car5_iqr`, `prec_neff`, `prec_hit_rate`, `prec_placebo_z`. They are built under the same time guard, so they contain only responses that had already completed.

**Asset panel** (proposed): SPY, QQQ, IWM, the eleven sector SPDR funds, TLT, IEF, HYG, GLD, USO, UUP, EEM, EFA. Company events add the subject stock and its sector fund.

## 9. Ripple: a second-order effects map

### 9.1 What it does

Ripple keeps a dated graph of economic links between companies. When an event hits one company, the shock is propagated along the links that existed on that date, and Qlib learns whether, and how fast, linked companies follow. The outputs are a daily "next in line" report and a family of factors.

### 9.2 Why it might work, and the honest prior

Published evidence says shocks travel slowly along economic links (`SRC`):

- Cohen and Frazzini (2008, Journal of Finance): buying companies whose customers did well last month and shorting those whose customers did badly earned 1.55% a month.
- Menzly and Ozbas (2010, Journal of Finance): supplier and customer industries predict each other's returns, less so where analyst coverage is high.
- Ali and Hirshleifer (2020, Journal of Financial Economics): momentum among stocks that share analysts earns 1.68% a month and subsumes the customer, supplier, industry and geographic versions.

The evidence against a daily version is just as clear. Those results are monthly. A 2023 preprint (Pinchuk, arXiv 2301.11394) finds the customer spread fell to 0.62% a month for 2005-2018, not significant when value-weighted, with nothing at 1 to 10 days and an effect only at 20 and 30 days, equal-weighted. A vendor study of S&P 500 suppliers finds no 1-day effect.

So the prior for large caps is no effect at 1 and 5 sessions and a small one, at best, at 20. Ripple tests 1, 5, 20 and 60 sessions and leads with 20. The design in 9.6 is built so that "no" is a clear answer, and the daily map (9.8) is useful as an explanation tool even if the factors add nothing.

### 9.3 Link sources

| Channel | Source | Clock | Model call |
|---|---|---|---|
| Peer or competitor | Hoberg-Phillips text-based industry links: **not used.** Free to download, but keyed by Compustat `gvkey` with no free crosswalk to ticker or CIK found (`SRC`). | n/a | n/a |
| Peer, built ourselves | Embeddings of 10-K business descriptions, top-k by cosine | The later of the two filings' acceptance times | Embedding |
| Customer and supplier | Extracted from 10-K text (the major-customer note, business and risk sections) and 8-Ks. Expect sparse coverage: the accounting rule requires disclosing that a customer exceeds 10% of revenue, but not its name (`SRC`). | Acceptance time of the source filing | Parser, with a link schema |
| Commodity exposure | Rolling beta of the stock to commodity fund returns; also extraction from 10-K risk factors | Price date; acceptance time | None; parser |
| Country exposure | Regional revenue segments from filings | Acceptance time | Parser or structured data |
| Statistical control | Rolling 250-session residual-return correlation, top-k | Price date | None |

### 9.4 Link store

Each link is a row: source node, destination node, relation, weight, `valid_from_utc` (acceptance time of the source document), `valid_to_utc`, source document id, evidence span, extractor version. `graph_asof(session)` returns the links whose validity covers that session's cutoff. A link from an annual filing expires 15 months after its source unless a later filing restates it (proposed).

**Links come from documents, never from the model's memory.** Asking a model who supplies a company returns an undated answer drawn from everything it has read, including the future. A link has an evidence span found in a dated document, or it does not exist.

### 9.5 Shock and propagation

Two shock definitions, tested separately:

- **Price shock:** the source company's abnormal return on its event session. Needs no language model.
- **Text shock:** the direct news factor `news_signed_1d`.

Propagation, per channel `c`, at most two hops:

```text
ripple_c(t) = sum over k = 1..2 of  alpha^k * (A_c,t)^k * shock(t)
A_c,t  = row-normalized adjacency of channel c as of session t
alpha  = 0.5 (proposed)
```

Factors: `ripple_customer`, `ripple_supplier`, `ripple_peer`, `ripple_commodity`, `ripple_hop2`, each decayed with a 3-session half-life, and `ripple_unabsorbed`: the propagated shock minus the company's own abnormal return since the event, which is the part the price has not yet done.

### 9.6 Graph ladder and controls

| Rung | Graph |
|---|---|
| G0 | None (model M1) |
| G1 | Sector membership |
| G2 | Return-correlation graph |
| G3 | Text-similarity peers |
| G4 | Model-extracted customer, supplier and commodity links |
| Placebo | G4 with links shuffled so every node keeps its number of links |

For each rung, report incremental rank IC at 1, 5, 20 and 60 sessions. That is a diffusion curve: if spillover is slow, IC should persist at 20 and beyond. The model-built graph has to beat both G2 and the placebo. If the shuffled graph does as well, the links carry no information and only the shock does.

### 9.7 Model

LightGBM on M1 plus Ripple factors first. Qlib's `HIST` accepts a stock-to-concept matrix, but the matrix is static, with no date axis (`SRC`), so it cannot hold a dated graph unmodified. It, or a custom graph network, is considered only after the factors show signal.

### 9.8 The daily map

`predate ripple --date <session>` writes a report: the largest shocks of the session; for each, the linked companies by channel; the propagated size; how far each has already moved; and for every link the source document and evidence span.

## 11. Production pitfalls

1. **Letting the model predict.** Any field that asks for an outcome invites memory. Keep the schema about the text.
2. **Trusting publisher timestamps.** Use first-seen time, and model latency explicitly.
3. **Using ingestion time in a backfill.** It is the wrong decade.
4. **Loader order.** Sparse loader first with a left join silently drops most of the universe.
5. **Region default.** `qlib.init()` without `region="us"` applies Chinese lot sizes and price limits.
6. **Blanket NaN fill.** It turns missing prices into zeros.
7. **Recaps and opinion counted as news.** Without the novelty field and story clustering, stale stories dominate.
8. **Hallucinated tickers.** Resolve names in code against a dated security master.
9. **Overwriting parser output.** Every re-parse is a new vintage.
10. **Reporting pre-cutoff results as out-of-sample.** They are contaminated by model memory.
11. **Survivorship.** Free price data has only today's listings.
12. **Label and execution price out of step.** The label expression and `deal_price` must describe the same trade.
13. **No purge between train and valid.** `RollingGen` does not do it for you.
14. **Untracked trials.** The best of fifty configurations is not a discovery.
15. **Cost model shape.** Qlib's impact is quadratic in participation and never moves the fill price; do capacity analysis outside it.
16. **Analogs that have not finished.** A precedent's outcome is future information until its window closes.
17. **Links from memory.** An undated link is a leak.
18. **Schema features a decoder silently skips.** Use enums, and validate after decoding regardless.
19. **Purge shorter than the label.** The purge length must be derived from the label expression, not typed by hand.
20. **A feed outage that looks like a quiet day.** Zero-filled news factors cannot tell "no news" from "no data". Record feed coverage per session and exclude sessions without it.
21. **Half-days.** A fixed 16:00 cutoff is wrong on early-close sessions; cutoffs come from the calendar.
22. **Tuning decay on the whole sample.** Half-lives and age limits are hyperparameters and are chosen inside the training folds.
23. **GDELT on BigQuery.** The knowledge-graph table is measured in terabytes and the free allowance is 1 TiB a month. Dry-run every query, or use the raw 15-minute files.
